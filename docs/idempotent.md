# 幂等性防重系统 (冪等性二重送信防止システム) 🛡️

> 自定义 `@Idempotent` 注解 + Spring AOP + Redis 的防重复提交方案
> カスタム `@Idempotent` アノテーション + Spring AOP + Redis による二重送信防止ソリューション

---

## 快速开始 (30秒) / クイックスタート (30秒)

### 后端：添加注解 / バックエンド：アノテーションの追加
```java
@PostMapping("/api/order")
@Idempotent(timeout = 3000)  // 设定3秒内防重 / 3秒間二重送信を防止
public Order createOrder(@RequestBody Order order) {
    return orderService.create(order);
}
```

### 前端：传递 Token / フロントエンド：Tokenの送信
```javascript
const token = crypto.randomUUID();
fetch('/api/order', {
    method: 'POST',
    headers: { 'Idempotent-Token': token },
    body: JSON.stringify(orderData)
});
// 冲突时返回 409 / 重複時は 409 エラーが返却されます
if (response.status === 409) { showWarning('请勿重复提交 / 重複送信を避けてください'); }
```

## 核心特性 / 主な特徴

- **三种策略 / 3つの戦略**: `TOKEN` (基于前端Token/フロントトークンベース), `USER_ID` (基于用户ID/ユーザーIDベース), `PARAM_HASH` (基于参数哈希/パラメータハッシュベース)
- **分布式支持 / 分散環境対応**: 基于 Redis，支持集群部署 / Redis によるクラスタデプロイ対応
- **自动降级 / 自動フォールバック**: Redis 不可用时自动降级到本地缓存 / Redis 接続エラー時はローカルキャッシュに自動切替
- **低开销 / 低オーバーヘッド**: 整体额外开销 < 2ms / 追加ミリ秒数は2ms未満

---

## 策略对比 / 戦略の比較

| 策略 / 戦略 | 场景 / ユースケース | 说明 / 説明 |
|------------|-------------------|------------|
| `TOKEN` | 表单提交、创建操作 / フォーム送信、新規作成 | 前端通过 Header 传递 `Idempotent-Token` / フロント側からヘッダーで送信（推奨） |
| `USER_ID` | 金融操作、敏感提交 / 送金、重要な操作 | 自动绑定当前用户与参数 / 認証済みユーザー情報とパラメータを自動バインド |
| `PARAM_HASH` | 数据同步、库存扣减 / 同期処理、在庫引き当て | 基于请求参数内容自动计算哈希 / リクエストパラメータのハッシュ値で判定 |

---

## 故障排查 / トラブルシューティング

- **频繁 409 错误 / 409エラーが頻発する**:
  - 请检查前端每次请求是否生成了新的唯一 Token / リクエストごとに新規 Token を生成しているか確認してください。
- **Redis 无法连接 / Redisに接続できない**:
  - 系统控制台会打印降级日志，并自动切换为本地单机缓存运行，不影响单机业务 / コンソールに警告が出力され、自動的にメモリ内キャッシュに切り替わります（単一ノード動作は継続）。
